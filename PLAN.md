# HomeMade audit and delivery plan

The November 23, 2026 audit reviewed `3d58f89`. At that point the Next.js app covered discovery, sign-in, authoring, saved projects, profiles, chats, and category moderation. Express also served legacy EJS routes and Socket.IO handlers alongside the JSON API. Subsequent implementation updates below reflect the current working tree.

The findings below record the original audit and include items already addressed by this update.

Current local verification (November 24, 2026): the production frontend build succeeds with Webpack after clearing the generated `.next` directory, frontend lint exits successfully with 30 warnings and no errors, and the last successful installed dependency audit reported zero known vulnerabilities (a fresh registry check is currently network-blocked). The latest 27-test offline regression run predates the newest chat-storage, session/media, MongoDB rate-limit, and dependency upgrades; it has not been rerun. The built project page previously passed a fixture-based server-rendering check for a guest and owner. Accessibility changes were source-reviewed and built, but no interactive browser, screen-reader, contrast, or reflow audit has been performed. No live MongoDB, chat migration, OAuth, S3, hosting, or browser journey has been checked. Production rollout still needs those environment-specific checks, verified indexes, working email or deliberately disabled email entry points, and configured secrets, origins, proxy, and backups.

## Accessibility status

The code includes useful foundations such as a skip link, semantic navigation and landmarks, keyboard-operable buttons, selected live status messages, an error heading that receives focus, and keyboard controls for the project image dialog. This is not a completed accessibility audit and does not establish usability for every disability or support need. The project description editor now has a programmatic name and help-text relationship, and keyboard focus has a consistent visible outline. Remaining work includes reviewing every form and dialog with keyboard and screen-reader use, checking contrast and 200%/400% reflow, reducing motion where applicable, confirming image alternatives and error announcements, and testing representative journeys with assistive technology and people who use it.

## Original audit findings and release blockers

This table records the findings at `3d58f89`; it is historical evidence, not a list of unfixed defects. Use the implementation update above and the delivery checks below to determine what remains. In particular, legacy route containment and several authentication, upload, query, and draft fixes have since been implemented locally but still need the listed deployment and integration verification.

| Priority | Finding and impact | Remediation |
| --- | --- | --- |
| P0 | **Legacy profile writes bypass ownership and role controls.** The route requires a session, then passes the request body directly to the database for the addressed profile. The schema includes `role`, and the admin middleware trusts that stored role. The Next.js API handler has a self-edit check and sets fields explicitly. [Legacy update](controllers/profiles.js#L70) · [Profile schema](models/profile.js#L5) · [Admin middleware](middleware/middleware.js#L17) · [API update](controllers/api.js#L1257) | Retire the legacy write or share the guarded update service. Derive identity from the session, allowlist writable fields, and verify that role changes are restricted across every write path. |
| P0 | **Legacy chat bypasses conversation privacy.** The EJS detail handler loads chat history without checking membership. The socket room join lacks an authorization check, and the persistence helper lacks a participant check. Sender identification also expects an object where Passport stores a user ID, which makes the socket send path unreliable. The EJS live renderer places received text into `innerHTML`, creating an injection sink if messages reach that renderer. [Legacy chat](controllers/chats.js#L36) · [Socket handlers](bin/www.js#L37) · [Passport serialization](config/passport.js#L231) · [Live renderer](views/chats/chat.ejs#L86) | Retire legacy chat and socket events if Next polling is the supported path. If kept, authenticate the socket, authorize room joins and events, scope typing to participants, and render message text as text. Remove chat bodies from logs. |
| P0 | **Hidden projects remain accessible.** Public listings filter `visible`, but the JSON and EJS detail handlers fetch by ID alone. Legacy search and the legacy profile project lookup also lack a visibility filter. Comment and save actions need the same visibility policy. [API detail](controllers/api.js#L566) · [Legacy detail](controllers/projects.js#L82) · [Legacy search](controllers/search.js#L3) · [Legacy profile](controllers/profiles.js#L24) | Decide whether Hidden means private or unlisted and make the UI explicit. Default to owner-only for new hidden content. Centralize the read and interaction policy. For private photos, use access-controlled media and review previously issued public URLs. |
| P0 | **Account linking trusts matching email strings.** OAuth callbacks supply email claims to a helper that links accounts automatically and marks them verified. An existing unverified password account can keep its password after linking. Apple claims are decoded without explicit signature, issuer, or audience verification in application code. OAuth request binding also needs attention across providers. [Account linking](config/passport.js#L37) · [Apple callback](config/passport.js#L200) · [OAuth routes](routes/auth.js#L425) | Key sign-in on verified provider subject. Make cross-provider linking an authenticated and explicitly confirmed flow, handle pre-existing unverified accounts, add unique identity constraints after checking existing data, and verify OAuth state and OIDC claims with supported libraries. Disable providers until their flow is verified. |
| P1 | **Legacy project mutations bypass modern validation.** Create accepts owner and other model fields from the submitted body. Update checks the current owner but passes the request body through, including writable ownership fields. Legacy comment deletion has no author or moderator check. Legacy ratings also bypass the Next.js rating rules. [Legacy create](controllers/projects.js#L64) · [Legacy update](controllers/projects.js#L161) · [Legacy comments](controllers/projects.js#L207) | Disable obsolete mutation routes or route them through guarded services. Derive ownership and comment identity from the session. Enforce the agreed comment deletion and rating policy server-side. |
| P1 | **Upload handling risks memory consumption and orphaned objects.** Multer buffers whole files without size or type limits. Browser `accept` only filters file selection. S3 creation logs file objects, uses hard-coded URL construction, and lacks cleanup when an upload or database write fails partway through. [Upload setup](routes/api.js#L6) · [S3 service](services/s3Service.js#L1) · [Example configuration](.env.example) | Set request and per-file limits, verify and decode allowed image formats, cap image dimensions and total count, and use consistent S3 configuration and object keys. Store object IDs, clean up failed writes, and scope S3 credentials to the app's storage needs. [OWASP file upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) |
| P1 | **Installed dependencies match known advisory ranges.** The lockfile has Multer `1.4.5-lts.1` and Next.js `15.5.12`. The Multer advisory covers the installed parser. The Next.js advisory covers the installed version and describes a Server Components denial-of-service condition. Deployment reachability was unverified. [Lockfile](package-lock.json) · [Multer advisory](https://github.com/expressjs/multer/security/advisories/GHSA-4pg4-qvpc-4q3h) · [Next.js advisory](https://github.com/vercel/next.js/security/advisories/GHSA-q4gf-8mx6-v5v3) | Move to supported patched releases, rerun the full production dependency audit with registry access, and verify upload and App Router behavior against the updated lockfile. |
| P1 | **Auth and session lifecycle needs production safeguards.** Email delivery is a development logger, although production replies claim mail was sent. Password hashing is synchronous and auth routes have no app-level throttling. Verification and magic tokens are cleared after a read, leaving a concurrent reuse window. Sign-in and magic-link pages trust the redirect destination supplied in the URL. Sessions use the default in-memory store and omit explicit `Secure` and expiry settings. Logout is a GET. [Email routes](routes/auth.js#L157) · [Magic-link consumption](routes/auth.js#L353) · [Sign-in redirect](frontend/app/auth/sign-in/page.js#L95) · [Sessions](server.js#L69) | Configure real delivery or disable email entry points. Make token consumption atomic, remove tokens from logs and URLs after exchange, throttle auth requests, move expensive password work off the event loop, constrain redirects to the app origin, and use a durable session store with secure cookie settings and CSRF protection. Verify the chosen cookie strategy with OAuth callbacks and production hostnames. [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) |
| P1 | **Failure handling and public queries can overload the server.** Express 4 async handlers lack a common rejection wrapper, and parser errors fall through to EJS. Dedicated search sends the supplied pattern to MongoDB without the browse endpoint's escaping or length bound. Pagination is optional, and rating sort reads the full result set before paging. [API routes](routes/api.js#L10) · [Express error handler](server.js#L96) · [Search](controllers/api.js#L1310) · [Browse](controllers/api.js#L507) | Validate IDs and input types before controller work. Use structured JSON errors and a shared async boundary. Escape and bound search, require paginated list access, project summary fields, and move rating ordering and suitable indexes to MongoDB. Add request limits and readiness checks. |
| P1 | **Draft fallback can cross accounts on a shared browser.** Local storage uses one global key for all signed-in users. Cloud fetch errors bypass local recovery, and in-flight autosaves can overlap a newer edit or draft clearing. [Draft restore and autosave](frontend/app/projects/new/project-form.js#L478) · [Server draft](controllers/api.js#L632) | Key fallback drafts by profile, remove the old unscoped fallback, and add a user-controlled recovery path. Use ordered or versioned writes and prevent late saves from reviving cleared drafts. |
| P2 | **External links and web hardening need consistent rules.** Profile website/social values are stored as strings and the legacy profile view inserts them into link destinations. The modern rich-text path has sanitization, but general links and media need a shared policy. [Profile validation](controllers/api.js#L1257) · [Legacy links](views/profiles/show.ejs#L36) · [Rich-text sanitization](controllers/api.js#L69) | Validate and normalize HTTP(S) links centrally, apply safe rendering to old records, and configure appropriate security headers. Keep bearer tokens and sensitive values out of request logs. |

## Delivery order and acceptance checks

1. **Contain the exposed legacy surface.** Inventory affected routes and public media. Make the Next interface the supported entry point and disable duplicate legacy writes or route through shared policy. Complete checks with a guest, an owner, another signed-in maker, and an admin. Verify project visibility across direct links and discovery, and participant-only chat access across every remaining transport.
2. **Make auth, uploads and errors production-ready.** Upgrade patched dependencies, add session and CSRF handling, implement or gate email delivery, and validate uploads and external URLs. Add API integration tests for permission, invalid-input, retry, and expired-session cases. Make build, lint, and tests runnable in CI from a clean checkout. Update the README and configuration examples to match deployed S3, auth, and frontend environment settings.
3. **Finish the core maker loop.** Fix detail rendering and image references first. Align browse/search, then finish publish/edit and draft recovery, then refine save/rate/comment and profile entry points. Check the complete journey on desktop and a narrow mobile viewport with keyboard navigation, slow requests, an interrupted draft, and sample pre-migration records.
4. **Harden community features and operations.** Add chat pagination, hide/retry states and report/block. Improve moderator queues, add observability with redaction, and validate data migrations and backups before retiring the remaining EJS templates. Measure browse, detail and inbox response times with realistic fixtures.
